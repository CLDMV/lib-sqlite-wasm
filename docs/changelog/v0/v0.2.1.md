# `@cldmv/sqlite-wasm` v0.2.1 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/0.2.1`

---

## Overview

`dist/` is now one file per source module, in the same layout as `src/`, instead of four bundles that shared code through hashed `chunk-*.mjs` files. Every module still exists once, so `instanceof` keeps working across `@cldmv/sqlite-wasm`, `/host`, `/worker` and `/drizzle`. The public API, the import names and the wasm module are unchanged.

---

## 🐛 Bug Fixes

### `dist/` mirrors `src/` instead of hashed chunks ([#14](https://github.com/CLDMV/lib-sqlite-wasm/pull/14))

v0.1.0 and v0.2.0 built the four entry points with one tsup bundle and code splitting, which put the shared code into files named `chunk-<hash>.mjs`. Nothing in them said what they held, and the hashes changed on every build. The build now compiles each `src/**/*.mts` to `dist/**/*.mjs` at the same path with `tsc`, then minifies each file in place with esbuild (`keepNames`, source maps back to `src/`). Nothing is bundled: the entries share modules through plain relative imports, so there is still one copy of each class.

- `./host` and `./worker` now resolve to `dist/worker/host.mjs` and `dist/worker/client.mjs`. The package's import names are the same.
- The Node and browser loaders find `sqlite3.wasm` at `../sqlite3.wasm` from `dist/core/`, still the same `dist/sqlite3.wasm`. Bundlers that copy the wasm from the `new URL(..., import.meta.url)` pattern keep doing so.
- tsup is no longer a dev dependency; `scripts/build-js.mjs` replaces `tsup.config.mjs`.
- A test checks that `dist/` has exactly one `.mjs` per source module and no generated chunks.

## 🔧 CI & tooling

- The bundle-size check measured `dist/**.mjs`, which only matches files at the top of `dist/`. It now uses `dist/**/*.mjs`, `dist/**/*.cjs` and `dist/**/*.wasm`.
