# `@cldmv/sqlite-wasm` v0.2.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/0.2.0`

---

## Overview

Adds `bytes()`, a Drizzle blob column that holds a plain `Uint8Array`, so browser apps can store binary data through Drizzle without a `Buffer` polyfill. The release also adds a design document and fuller npm keywords. Nothing else changed at runtime, and the wasm module is the same build as v0.1.0.

---

## ✨ Features

### `bytes()` blob column for Drizzle ([#8](https://github.com/CLDMV/lib-sqlite-wasm/pull/8))

`@cldmv/sqlite-wasm/drizzle` now exports `bytes()`, a blob column whose value is a `Uint8Array`:

```js
import { bytes } from "@cldmv/sqlite-wasm/drizzle";
import { integer, sqliteTable } from "drizzle-orm/sqlite-core";

export const files = sqliteTable("files", {
	id: integer("id").primaryKey(),
	data: bytes("data").notNull()
});
```

Drizzle's own `blob()` modes call Node's `Buffer`, which browsers don't have, so using them in a page or worker needs a polyfill. `bytes()` never touches `Buffer`. Blobs already come back from the database, and through the worker client, as `Uint8Array`, so it passes values straight through. It stores a `blob`, so drizzle-kit generates the same column as `blob("data")`. It is covered in Node, CommonJS and `dist/`, through the worker client, and in Chromium with no `Buffer` defined.

## Upgrade notes

- No breaking changes. Drop-in for v0.1.0.
- Apps that installed a `Buffer` polyfill only for Drizzle blob columns can switch those columns to `bytes()` and drop the polyfill. The stored data is the same `blob`, so no migration is needed.
